Location: Section "Schedule changes" (s3), form error (s3-form-promo-error)
Evidence: `<input id="promo" type="text" aria-invalid="true"><span class="error-text" id="s3-form-promo-error">Error.</span>`
Problem: The error message "Error." is not descriptive (fails WCAG 3.3.1) and is not programmatically associated with the input via `aria-describedby`, so screen reader users won't know what's wrong or that the message relates to this field; additionally the field is marked invalid by default before any user interaction.
Fix: Add `aria-describedby="s3-form-promo-error"` to the input, write a descriptive message (e.g., "Promo code is invalid or expired"), and only set `aria-invalid="true"` after validation fails.
