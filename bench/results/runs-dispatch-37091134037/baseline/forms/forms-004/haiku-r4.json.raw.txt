Location: row-member input element
Evidence: `placeholder="Must be 8 digits"` with `type="text"` and no pattern or maxlength attribute
Problem: The placeholder promises 8-digit validation but the field doesn't enforce it; users can enter any text.
Fix: Add `pattern="[0-9]{8}" maxlength="8"` to the input element.

Location: row-shipspeed select option elements
Evidence: `<option>Standard</option>` and similar options lack value attributes
Problem: Without value attributes, the form will submit the option's text content (e.g., "Standard") instead of a controlled value.
Fix: Add explicit value attributes to each option, e.g., `<option value="standard">Standard</option>`.

Location: row-name and row-legalname fields
Evidence: "Full name" field with name="full_name" and "Your name" field with name="legal_name"
Problem: Both fields ask for a person's name with different field names and no clear distinction, creating confusion about which one is required.
Fix: Remove one field or clarify the distinction in the labels (e.g., "Full name" vs. "Legal name for contracts").

Location: row-contacttime input element
Evidence: `<input id="contacttime-input" name="contact_time" type="text" required="">`
Problem: type="text" is too vague for a contact time preference; the expected format is unclear to users.
Fix: Change to `type="time"` or add a placeholder like `placeholder="e.g., 9am-5pm"` to clarify the expected format.

Location: viewdetails-btn button element
Evidence: `<button id="viewdetails-btn" type="button" style="padding:12px 20px;font-size:16px">View details</button>`
Problem: The button has no onclick handler or apparent integration with the form, making it non-functional.
Fix: Either add an onclick handler with functionality or remove the button if it's not needed.
