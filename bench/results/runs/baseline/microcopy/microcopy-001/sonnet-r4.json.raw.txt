Location: Signup form, email field, first message ("The connection dropped before this finished.")
Evidence: "Fires: on-blur"
Problem: A message describing a dropped network connection is triggered by the user leaving the field, not by a submission attempt or network event, so the stated cause of the error does not match the moment it appears.
Fix: Change the fire condition to the actual submit or network event that produced the failure, or rewrite the message so it makes sense as an on-blur event.

Problem: Two different messages are defined for the same field with the same placement, container, and trigger, and nothing in the document says which one wins if both conditions could be true at the same moment, such as a malformed address entered while the connection drops.

Location: Checkout form, payment method, first message ("Something went wrong. Contact support if this continues.")
Evidence: "Suggested fix: none"

Location: Checkout form, payment method, expiry date message
Evidence: "Fires: mid-keystroke"
Problem: Validating the card expiry mid-keystroke means the message can appear before the user has finished entering the date, for example while typing "12" before adding the year, producing a false expired-card warning on a date that is not yet complete.
Fix: Change the fire condition to on-blur or to trigger only once a complete date has been entered.
