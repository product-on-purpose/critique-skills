Location: Signup form, email field — first message block ("The connection dropped before this finished."), "Predictable mistake" field
Evidence: Message: "The connection dropped before this finished." / Predictable mistake: yes
Problem: A dropped network connection is a system/infrastructure failure, not something the user did wrong, so classifying it as a "predictable mistake" mischaracterizes the error.
Fix: Change "Predictable mistake" to "no" for this entry, or add a separate category for system/transport failures distinct from user-input mistakes.

Location: Signup form, email field — first message block, "Fires" field
Evidence: "Fires: on-blur"
Problem: A connection dropping is a transport/submission failure that would surface when data is sent over the network, not simply when the user leaves the field; "on-blur" doesn't match how this failure could be detected.
Fix: Change "Fires" to "on-submit" (or "on async request") to reflect when a network failure would actually occur.

Location: Checkout form, payment method — first message block, Message field

Location: Checkout form, payment method — second message block ("The expiry date on this card has passed..."), "Fires" field
Evidence: "Fires: mid-keystroke"
Problem: Validating expiry against "has passed" while the user is still typing will flag the field as expired before a complete date has even been entered, producing false-positive errors mid-entry.
Fix: Change "Fires" to "on-blur" (or on-submit) so validation runs only after the full date is entered.
