Location: Form element
Evidence: `<form id="form">`
Problem: Form lacks a method attribute, which defaults to GET. Account creation forms containing password fields should use POST to prevent credentials from appearing in browser history or server logs.
Fix: Add `method="post"` to the form element: `<form id="form" method="post">`

Location: Full name field and Your name field
Evidence: `<input id="name-input" name="full_name"...` and `<input id="legalname-input" name="legal_name"...`
Problem: Two separate required fields both collect the user's name with different field names ("full_name" vs "legal_name"), creating ambiguity about whether they serve different purposes or are duplicates.
Fix: Remove one of the duplicate fields, or clearly distinguish their purposes in the labels (e.g., rename "Your name" to something more specific like "Legal name on account").

Location: Preferred shipping speed select (rows containing "Standard", "Express", etc.)
Evidence: `<option>Standard</option><option>Express</option><option>Overnight</option><option>Next-day</option><option>International</option>`
Problem: Option elements have no value attributes, so the form will submit the display text as data instead of normalized values.
Fix: Add value attributes to each option: `<option value="standard">Standard</option><option value="express">Express</option>` etc.

Location: Membership number field
Evidence: `<label id="member-label" for="member-input">Membership number (8 digits)</label>` with `placeholder="Must be 8 digits"`
Problem: The label and placeholder both specify an 8-digit requirement, but the input lacks validation attributes (pattern, maxlength, minlength) to enforce it.
Fix: Add `pattern="[0-9]{8}" maxlength="8"` attributes to the input.

Location: Preferred contact time field
Evidence: `<label id="contacttime-label"...>Preferred contact time</label>` followed by `<input id="contacttime-input" name="contact_time" type="text" required="">`
Problem: A text input cannot properly capture a time preference; users have no guidance on format and the field accepts any text.
Fix: Change `type="text"` to `type="time"`, or replace with a select element offering predefined options like "Morning", "Afternoon", "Evening".

Location: Organization name input
Evidence: `<input id="org-input" name="organization" type="text" style="font-size:16px" required="">`
Problem: Inline style is applied only to this input; other form fields lack this styling, and it should be managed in CSS for consistency.
Fix: Move `style="font-size:16px"` to a CSS stylesheet and apply it via a class or selector.

Location: Preferred contact time label
Evidence: `<label id="contacttime-label" for="contacttime-input" style="display:block">`
Problem: Inline style should be managed in a CSS stylesheet, not embedded in HTML.
Fix: Remove the inline style and apply `display: block` via CSS.

Location: View details button
Evidence: `<button id="viewdetails-btn" type="button" style="padding:12px 20px;font-size:16px">View details</button>`
Problem: Button has inline styles while the submit button does not, creating visual inconsistency; additionally, the button's purpose is unclear with no onclick handler visible.
Fix: Move inline styles to CSS and either add an onclick handler, title attribute, or remove the button if it serves no purpose.
