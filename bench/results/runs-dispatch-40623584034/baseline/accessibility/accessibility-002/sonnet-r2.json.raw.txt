Location: `<head>` — `<meta name="viewport" content="width=device-width, initial-scale=1, user-scalable=no" id="head-viewport">`
Evidence: `user-scalable=no`
Problem: Disabling user scaling prevents pinch-to-zoom, which blocks low-vision users from magnifying content and violates WCAG 1.4.4 (Resize Text).
Fix: Remove `user-scalable=no` (and any `maximum-scale` restriction) from the viewport meta tag.

Location: `<title id="head-title">` vs `<h1 id="main-h1">`
Evidence: Title is "Cascadia Regional Transit: Service Announcements" but the H1 reads "Fare and service announcements"
Problem: The page title and main heading describe the page differently, which can confuse users navigating by browser tab/title and screen-reader users who rely on title-to-heading correspondence.
Fix: Make the title and H1 consistent, e.g. title "Cascadia Regional Transit: Fare and Service Announcements".

Location: Section s1, paragraph `#s1-p1`
Evidence: `style="color:#999999"` on "Passengers should review the updated schedule at any station kiosk..."
Problem: #999999 text on a white background yields roughly a 2.85:1 contrast ratio, failing WCAG AA's 4.5:1 (and even the 3:1 large-text) minimum.
Fix: Darken the text color to at least #595959 (or remove the inline style and use the default body text color) to meet contrast requirements.

Location: Section s1, `#s1-p1` and `#s1-p2`

Problem: The sentence is reused verbatim across two unrelated statements (kiosk schedule review and mobile-app fare adjustment), producing duplicated boilerplate that doesn't logically follow from the fare-adjustment context.
Fix: Remove the duplicated sentence from one paragraph, or write a sentence specific to each action's actual turnaround behavior.

Location: Section s3, `<div class="status-card" role="status" id="s3-statuscard" style="height:60px;overflow:hidden">`
Evidence: `style="height:60px;overflow:hidden"`
Problem: The fixed height with `overflow:hidden` can visually clip the message for sighted users while screen readers (via `role="status"`) still announce the full text, creating an inconsistent experience across modalities.
Fix: Remove the fixed height/overflow clipping and let the card grow to fit its content, or truncate the text itself with an accessible "read more" affordance.

Location: Section s3, `<button id="s3-button1" style="border:1px solid #9d9d9d">`

Problem: The #9d9d9d border against a white background gives roughly 2.71:1 contrast, failing WCAG 1.4.11's 3:1 minimum for UI component boundaries.

Location: Section s3, `<div class="icon-delete" role="button" tabindex="0" aria-label="Delete item" id="s3-customcontrol">`

Problem: A custom `div` is reimplementing native button semantics (role, tabindex, label) rather than using a real `<button>`, which risks missing built-in keyboard activation (Enter/Space) and other native behaviors.
Fix: Replace with a native `<button type="button" aria-label="Delete item">` containing the icon.

Location: Section s3 form, `<input id="promo" type="text" aria-invalid="true">`

Fix: Set `aria-invalid="false"` (or omit it) by default and only set it to `"true"` dynamically after validation fails.
