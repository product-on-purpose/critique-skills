Location: `<html lang="translanguage" id="html">`
Evidence: `lang="translanguage"`
Problem: "translanguage" is not a valid BCP 47 language code, so screen readers and browsers cannot determine the page's language for pronunciation/translation purposes.
Fix: Set `lang` to the actual content language, e.g. `lang="en"`.

Location: Section s3, `<div class="status-card" role="status" id="s3-statuscard">`
Evidence: `role="status"` wraps "Local residents can check real time arrivals through the online portal. A confirmation message follows once the request is processed."

Location: Section s3, `<form id="s3-form">`
Evidence: `<form id="s3-form">` has no `action` or `method` attribute; none of its inputs (`select#topic`, `#email`, `#phone`, `#promo`) have a `name` attribute.
Problem: Without `name` attributes on the fields (and an `action`/`method` on the form), a standard form submission would send no usable data to any server endpoint.

Location: Section s3 form, phone field

Problem: The label tells users the field is required, but the input itself lacks the `required` attribute (and no `aria-required`), so there's no actual enforced or announced validation requirement.

Location: Section s3 form, promo field
Evidence: `<input id="promo" type="text" aria-invalid="true">`
Problem: `aria-invalid="true"` is hardcoded in the markup regardless of actual input state, so screen readers will announce the field as invalid even before the user has entered anything.
Fix: Only set `aria-invalid="true"` dynamically after validation fails, defaulting to `false` or omitted on load.

Location: Section s3 form, promo field and its error text

Problem: The error message is not programmatically associated with the promo input (no `aria-describedby`), so screen reader users focused on the field won't hear why it's invalid.
Fix: Add `aria-describedby="s3-form-promo-error"` to the promo input.

Location: Section s3 form, submit button
Evidence: `<button type="submit" class="btn-primary" id="s3-form-submit" aria-label="Send form now">Submit</button>`
Problem: The accessible name ("Send form now") does not contain the visible label text ("Submit"), which violates WCAG 2.5.3 (Label in Name) and confuses speech-input/screen-reader users trying to match what they see to what they hear.
Fix: Remove the `aria-label` (letting the visible "Submit" text serve as the accessible name) or make the `aria-label` include "Submit."
