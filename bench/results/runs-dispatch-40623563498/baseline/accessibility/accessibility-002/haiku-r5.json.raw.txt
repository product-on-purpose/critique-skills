Location: Section "Accessibility improvements", first paragraph (id="s1-p1")
Evidence: style="color:#999999"
Problem: Gray text (#999999) has insufficient contrast (~1.7:1) against white background, violating WCAG AA standards (minimum 4.5:1 for normal text).
Fix: Change the color to a darker value, such as #555555 or #000000.

Location: Section "Schedule changes", paragraph (id="s2-p1")
Evidence: "Local residents can check real time arrivals through the mobile app. A confirmation message follows once the request is processed."
Problem: The text is contradictory—viewing real-time arrivals is a view-only action and does not require processing a request.
Fix: Remove the second sentence or replace it with text that actually describes a request-based action.

Location: Section "Weekend service", status card container (id="s3-statuscard")
Evidence: style="height:60px;overflow:hidden"
Problem: The fixed height of 60px combined with overflow:hidden will truncate the paragraph content inside.
Fix: Remove the height and overflow properties to allow the content to display fully.

Location: Section "Weekend service", delete button control (id="s3-customcontrol")
Evidence: <div class="icon-delete" role="button" tabindex="0" aria-label="Delete item">
Problem: A div with role="button" is not semantic and lacks built-in keyboard support (Enter/Space key handling).
Fix: Replace with a <button> element: <button class="icon-delete" aria-label="Delete item"><img src="/img/trash-icon.svg" alt=""></button>

Location: Section "Weekend service", link in paragraph (id="s3-link1")
Evidence: <a href="/fares/history">read the accessibility improvements list</a>
Problem: Link text "read the accessibility improvements list" does not match the destination "/fares/history".
Fix: Either change the text to "read the fare history" or change the href to point to an actual accessibility improvements page.

Location: Section "Weekend service", form label (id="s3-form-topic-label")
Evidence: <label for="topic-alt"> paired with <select id="topic">
Problem: The label's for attribute ("topic-alt") does not match the select element's id ("topic"), so they will not associate.
Fix: Change the label's for attribute from "topic-alt" to "topic".

Location: Section "Weekend service", form promo input (id="s3-form-promo")
Evidence: <input id="promo" type="text" aria-invalid="true">
Problem: The input has aria-invalid="true" set before any validation or form submission, falsely claiming the field is in an error state.
Fix: Remove aria-invalid or set it to "false", changing it to "true" only after validation determines an actual error exists.
