# 0023 - v0.1.0 measurement basis: two pinned model tiers and k=5

## TL;DR
- **Decision:** every published v0.1.0 number is measured on exactly two pinned model tiers, `claude-haiku-4-5-20251001` and `claude-sonnet-5`, at k=5 runs per (skill, artifact, tier). That pair plus k=5, against corpus hash `602ff4cf391e50f70038a9119a8bfbc076fa2cc3b05fa9beba49f475e5880dd5` (23 artifacts, generator 0.1.0), is the measurement basis of run set `p3-2026-07-31`. It resolves [R3 (baseline model tiers to pin)](../release-plans/plan_v0.1.0/plan_v0.1.0.md).
- **The grid:** 23 artifacts x 2 tiers x k=5 x 2 conditions (skill and frozen baseline) = **460 envelopes**, all present, all contract-valid, none quarantined.
- **Why two and why five:** two tiers is the minimum that satisfies [methodology section 8](../../explanation/methodology.md) ("at least two model tiers") and the only number at which a cheap-tier user and a mid-tier user both see a figure that is theirs. k=5 is fixed by methodology section 8 and yields C(5,2)=10 pairwise Jaccard comparisons per artifact, which is the smallest k where a consistency figure is a mean rather than an anecdote.
- **Consequence to state publicly:** these numbers decay. Any change to a tier ID, to k, or to the corpus hash invalidates the published tables and requires a new run set with a new identifier.
- **Status:** Accepted (2026-07-31).

## Context and problem statement

[Methodology section 8](../../explanation/methodology.md) requires baseline comparison "on at least two model tiers" and consistency at "k=5", and requires results tables to "pin model IDs and dates, because these numbers decay". [R3 (baseline model tiers to pin)](../release-plans/plan_v0.1.0/plan_v0.1.0.md) recommended haiku-4-5 and sonnet-5 with the exact IDs to be pinned at P3 run time, and left the row Open until that happened.

P3 has run. The exact IDs used, k, and the corpus identity now exist as facts in [`bench/results/measurement-manifest.json`](../../../bench/results/measurement-manifest.json) and in every one of the 460 run envelopes. What does not exist is a decision record saying that this specific combination is the declared basis for the version, as distinct from whatever happened to be convenient on the day. Without that record, a future reader cannot tell whether a differing number in v0.2 reflects a better skill or a different measurement.

## Decision drivers

- **Methodology sets the shape, not the values.** Section 8 fixes "at least two tiers" and "k=5". The IDs and the corpus are run-time facts that have to be pinned somewhere durable and human-readable, not left implicit in 460 JSON files.
- **A tier alias is not a pin.** "Haiku" and "Sonnet" name moving targets. `claude-haiku-4-5-20251001` is dated and immutable; `claude-sonnet-5` is the tier's release identifier as invoked. Both are recorded exactly as they appear in `run.model` on every envelope, so a table row and its envelopes join on a string, not on an interpretation.
- **The cheap tier must be one of the two.** Most of the unflattering findings in this run set are haiku findings. A basis that measured only a strong tier would publish numbers most users will not see. Pinning haiku is what makes the published figures honest for the tier a cost-sensitive user actually runs.
- **k must be affordable across the whole grid.** k=5 on 23 artifacts across two tiers and two conditions is already 460 model-backed runs. Raising k tightens the consistency estimate and multiplies the grid; lowering it below 5 drops the pair count per artifact from 10 to 6 or 3 and makes a single divergent run dominate the mean.
- **The basis has to be stated as decaying.** A version-pinned number that is quoted later without its basis becomes a false claim about a model that no longer behaves that way. Recording the basis as a decision, not just as data, is what makes "these numbers are from 2026-07-31 on these two IDs" a maintained statement rather than a footnote.

## Considered options

1. **Two pinned tiers (haiku-4-5-20251001, sonnet-5) at k=5 (chosen).** Meets methodology exactly, covers the cheap and mid tiers, affordable at 460 runs, and is what was actually executed.
2. **Three tiers, adding a frontier tier.** Rejected for v0.1.0. It would raise the grid to 690 runs for a tier whose numbers would be the most flattering and the least representative of routine use, and methodology asks for at least two, not for the best available. Worth revisiting in v0.2 as an additional column, not as a replacement.
3. **One tier.** Rejected: it violates methodology section 8's floor and would hide the tier gap, which is one of the more informative findings in this run set (every core skill measures materially worse on haiku than on sonnet).
4. **k=3 to halve the grid.** Rejected: 3 pairwise comparisons per artifact is not a distribution, and consistency is the metric [ADR 0022 (consistency floor)](0022-consistency-floor-overall-lane-min-core.md) gates the stretch skills on. Cheapening the input to the gate to save runs is the wrong trade.
5. **k=10 for a tighter consistency estimate.** Rejected on cost for v0.1.0 (920 runs) with no expectation that the ranking changes; the spread between skills here is far larger than the plausible sampling error at k=5.

## Decision outcome

Option 1. The declared v0.1.0 measurement basis:

| Element | Value |
|---|---|
| Run set | `p3-2026-07-31` |
| Date measured | 2026-07-31 |
| Tier 1 (alias `haiku`) | `claude-haiku-4-5-20251001` |
| Tier 2 (alias `sonnet`) | `claude-sonnet-5` |
| k (runs per skill per artifact per tier) | 5 |
| Pairwise comparisons per artifact per cell | C(5,2) = 10 |
| Corpus | 23 scored artifacts, 6 domains, generator 0.1.0, `toy` excluded |
| Corpus hash | `602ff4cf391e50f70038a9119a8bfbc076fa2cc3b05fa9beba49f475e5880dd5` |
| Root seed | `b7470f08a0096e0192161ee2b062cb16` |
| Contract version | 1.0.0 |
| Skill versions | all six at 0.1.0 |
| Baseline | `baseline-generic` 1.0.0, frozen prompt, fixed post-processing rule |
| Grid | 23 x 2 tiers x 5 runs x 2 conditions = 460 envelopes |
| Coverage achieved | 460 of 460, zero cells below the k=4 floor, zero quarantined |

**Not part of the basis.** The two envelopes under `bench/results/runs/steering/` are a prompt-injection-resistance probe carrying the [ADR 0014 (stripped-context run field)](0014-stripped-context-run-field.md) `run.stripped_context` field. They are contract-valid and stay on disk, but they are outside the 460-run grid and must be excluded when rescoring; including them changes `critique-clarity` on sonnet from 20 scored artifacts to 22 and from 40 consistency pairs to 51. [`bench/results/README.md`](../../../bench/results/README.md) carries the exclusion in the reproduction recipe.

**What invalidates the published numbers.** Any one of: a different model ID on either tier, a different k, a corpus whose hash differs from the value above, a change to `bench/baseline/prompt.txt` or to `bench/baseline/postprocess.py`'s mapping rule, or a contract version bump that changes what a finding means. Each requires a new run set identifier and a fresh full grid. Partial re-runs mixed into an existing run set are not permitted, because a table row would then span two bases.

## Consequences

**Positive:** every published figure is now traceable to a named basis rather than to an implied one, and the decay claim in methodology section 8 has something concrete to point at. Pinning the cheap tier alongside the mid tier means the published numbers include the worst realistic case rather than the best one, which is the difference between a benchmark and an advertisement.

**Negative:** two tiers is the floor, not a survey, so nothing here says how these skills behave on a frontier model or on a non-Anthropic model, and a reader is entitled to assume nothing. k=5 gives a consistency estimate with real sampling noise: `critique-argument` on haiku sits 0.062 above the [ADR 0022](0022-consistency-floor-overall-lane-min-core.md) floor, a margin well inside what a different set of five runs could plausibly move. The basis also freezes the release to a corpus that is entirely generated, so a change in corpus design in v0.2 breaks comparability with v0.1.0 numbers even if the skills are untouched.

**Neutral:** the 460-run grid took two conditions to fill because the frozen baseline is measured on exactly the same basis as the skills. That doubles the run count and is the reason a baseline comparison is like-for-like at all.
